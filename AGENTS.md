# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

friendlyfolio is the self-hosted photo gallery for Friendly.rb Conf (https://photos.friendlyrb.com). It replaced the hosted wfolio service and holds only the conference's own galleries: no customer accounts, no sign-up, no client proofing. Friendly.rb ran three editions (2023–2025) and **no future editions are planned**, so write copy in the past tense.

It is a Rails 8.1 app on SQLite with Avo as the admin, deployed by Hatchbox to one box behind Cloudflare. Photos live in Cloudflare R2 (`config/storage.yml`, service `r2`).

The look matches the conference site, https://friendlyrb.com, whose source lives in a separate Jekyll repository. The nav, footer, icons, colours and fonts are ported from it, so change them in step with it.

## Commands

```bash
bin/setup                    # install gems, prepare the database, start bin/dev
bin/dev                      # web + Tailwind watcher + Solid Queue worker
bin/rails test               # the suite
bin/rubocop                  # lint (rubocop-rails-omakase)
bin/brakeman --quiet --no-pager --exit-on-warn --exit-on-error
bin/bundler-audit check --update
bin/importmap audit
bin/ci                       # all of the above, as config/ci.rb lists them
docker compose up --build    # the production image locally (see compose.yaml)
```

- **Ruby 3.4.5** (`.ruby-version`). The macOS system Ruby is too old to run `bundle`. Without a modern Ruby, run commands in the `ruby:3.4.5` Docker image, as CI does.
- **libvips must be able to encode AVIF.** Half of each photo's variants are AVIF. A libvips without the AV1 encoder fails every baking test with `heifsave: Unsupported compression`. On Debian/Ubuntu, install `libvips42 libheif-plugin-aomenc libheif-plugin-dav1d`; on macOS, `brew install vips`.
- **CI** (`.github/workflows/ci.yml`) runs RuboCop, the three audits, the suite plus seeds, and a production asset build on every PR, all inside `ruby:3.4.5`. A failing check blocks the merge.

## How it fits together

- **Routes** (`config/routes.rb`): galleries sit at the root (`/:gallery_slug/:section_slug/photos/:id`), with the slugs constrained so they cannot swallow reserved prefixes. Add any new top-level path to `RESERVED`. The admin (`/avo`, `/admin/imports`) is drawn inside `authenticate :user`, so those routes do not exist for anonymous visitors.
- **Publication gate:** every public controller re-derives visibility (`admin_signed_in? ? Gallery.all : Gallery.published`), and sections and photos are always looked up through the authorised gallery. Keep both rules for any new public path.
- **Photos** (`app/models/photo.rb`): nine declared variants (thumb, wall, zoom, large in AVIF and WebP, plus `share_jpeg`). `Photo.displayable` is the only thing that may be rendered publicly. It requires `derivatives_ready_at` **and** `has_location_data: false`.
- **Baking:** `BakePhotoVariantsJob` handles single uploads, and `photos:preprocess` handles bulk imports (`lib/tasks/photos.rake`, with a runbook at the top of the file). `photos:verify` is the gate before publishing.
- **Front end:** Propshaft, importmap and Stimulus (`app/javascript/controllers/`). Styles are plain CSS in `app/assets/stylesheets/application.css`; the Tailwind build is little more than the reset. There is no Node toolchain.
- **SEO:** views declare metadata with `seo title:, description:, image:, ...` (`app/helpers/seo_helper.rb`), not `content_for`. The layout turns it into the title, description, canonical, Open Graph and Twitter tags, and JSON-LD. `/sitemap.xml` and `/robots.txt` are generated by `SitemapsController`.

## Rules that are easy to break

- **No published original may carry GPS.** The download button serves the photographer's original byte for byte, so GPS in it publishes where an attendee was standing.
  - The gate lives in `Photo.displayable`. Never mark a photo ready without it.
  - `ImageMetadata.located?` fails closed. An unreadable image, or a scan that errors, counts as located.
  - It checks EXIF fields and the XMP packet.
- **Absolute URLs come from configuration, never the request.** Use `absolute_url` / `canonical_url` in `SeoHelper`. `request.host`, `request.base_url` and `request.original_url` follow a client-sent `X-Forwarded-Host`, and public pages are edge-cached for 5 minutes. Redirects that land in public responses use relative paths (see `PhotosController#download`).
- **Cache headers:** `set_cache_headers` makes anonymous pages `public, max-age=300` with no session cookie, and sends `Vary: Turbo-Frame`. Admin responses, and any response carrying a flash, are `private, no-store`. New public controllers need the same `before_action`.
- **Content-Security-Policy** (`config/initializers/content_security_policy.rb`): scripts only from this origin, plus the importmap tags, which carry a nonce automatically. Never add inline `<script>`, `onclick=` or `javascript:` URLs; write a Stimulus controller. Never build HTML strings from data, especially names from dropped folders: create nodes and set `textContent`.
- **Never set `config.active_storage.urls_expire_in`, and treat `SECRET_KEY_BASE` as permanent.** Both would invalidate every cached and shared image URL.
- **Unpublishing does not revoke image URLs.** That is an accepted limit, pinned by `test/integration/unpublished_bytes_test.rb`. Retraction means deleting the photo.
- **Sign-in limits** are enforced in `Users::SessionsController` (`rate_limit`, per IP and per email) after routing. Rack::Attack only sheds floods early.
- **Avo:** every signed-in user is a full admin (`authorization_client = nil`), which is deliberate. Avo's `<head>` loads the app's importmap through `app/views/avo/partials/_head.html.erb`, so app controllers work in custom tools such as `/avo/import_photos`. Update Avo with the upgrade guide, not just `bundle update` (see `.claude/skills/avo/SKILL.md`).

## Conventions

- Comments explain *why* a line exists, often the incident that caused it. Keep that density and voice, and do not strip them.
- Tests are Minitest integration and model tests, with no system tests. Minitest 6 has no `Object#stub`; use the `stubbing` helper in `test/test_helper.rb`. Build fixtures that carry GPS inside the test; never commit an image with real coordinates.
- Commits follow Conventional Commits (`feat(web):`, `fix(security):`, `perf:`, `ci:`).
- Accessibility: interactive text is navy `#012B7F` or red-600 `#dc2626` (brand red `#FF3A36` and yellow fail contrast as text), and targets are at least 44px tall.

## Do not

- Commit photos, `storage/` contents, `.env` files or `config/*.key`.
- Run `photos:preprocess` against production from a laptop without reading the README's "copy up" warning. The first import replaces the production database.
- Preview an unpublished gallery on the deployed site; review it locally. Its image URLs are cached publicly forever.
- Push to `main`. Work on a branch and open a PR.

## Before you finish

1. `bin/rails test`, `bin/rubocop` and `bin/brakeman` pass (in Docker if needed).
2. For view or CSS changes, check the page at about 390px and at desktop width, with no console errors (watch for CSP violations).
3. For new or changed pages, check the rendered `<head>`: title, description, canonical, `og:image`, and JSON-LD that parses.
